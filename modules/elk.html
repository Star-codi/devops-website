ELK Stack — Elasticsearch, Logstash & Kibana

Metrics vs Logs — Two Different Problems

You already know Prometheus and Grafana from the Monitoring module. Prometheus answers: "How many requests per second? What's the CPU usage? How many errors in the last 5 minutes?" These are metrics — numbers over time.

But when something goes wrong, you need to answer: "What exactly happened? Which user triggered it? What was the full error message? What was the sequence of events?" That's a logs problem — and that's what the ELK Stack solves.

🏥 Analogy — Hospital Monitors vs Medical Records

Prometheus/Grafana = the heart rate monitor. Shows live numbers, alerts when something spikes. The ELK Stack = the patient's medical record. Captures every event — what happened, when, what the doctor said, what medication was given. You need both: the monitor to know something is wrong, the record to understand what and why.

The Three Components

🔎
Elasticsearch
The database and search engine. Stores all your logs as JSON documents. Allows full-text search across billions of log lines in milliseconds.
🔧
Logstash
The pipeline. Ingests logs from any source, parses and transforms them (extract fields, drop noise, add metadata), then sends them to Elasticsearch.
📊
Kibana
The dashboard. A web UI to search, filter, and visualise your logs. Build dashboards showing error rates, user activity, service health — from log data.

In modern stacks you'll also see Beats (lightweight log shippers installed on each server) and Logstash is sometimes replaced with Fluentd or Fluent Bit in Kubernetes environments.

Logstash Pipeline — Parsing Raw Logs

The pipeline file has three sections: input (where logs come from), filter (parse and transform), output (where to send them).

logstash/pipeline/main.conf
# ── INPUT ───────────────────────────────────────── input { beats { port => 5044 # receive from Filebeat } tcp { port => 5000 # receive raw TCP (apps can log directly) codec => json } } # ── FILTER ──────────────────────────────────────── filter { # Parse Nginx access log format if [fields][service] == "nginx" { grok { match => { "message" => '%{IPORHOST:client_ip} - - \[%{HTTPDATE:timestamp}\] "%{WORD:method} %{URIPATHPARAM:path} HTTP/%{NUMBER:http_version}" %{NUMBER:status_code} %{NUMBER:bytes}' } } mutate { convert => { "status_code" => "integer" } convert => { "bytes" => "integer" } } } # Parse JSON app logs (if your app logs JSON) if [fields][service] == "app" { json { source => "message" } } # Add environment tag mutate { add_field => { "environment" => "production" } remove_field => ["host", "agent"] } # Drop health check logs (noise) if [path] == "/health" { drop { } } } # ── OUTPUT ──────────────────────────────────────── output { elasticsearch { hosts => ["http://elasticsearch:9200"] index => "logs-%{[fields][service]}-%{+YYYY.MM.dd}" # Creates indices like: logs-nginx-2024.01.15 } }

Filebeat — Shipping Logs from Servers

Filebeat is a lightweight agent installed on each server. It tails log files and ships them to Logstash (or directly to Elasticsearch).

filebeat.yml
filebeat.inputs: - type: log enabled: true paths: - /var/log/nginx/access.log - /var/log/nginx/error.log fields: service: nginx # tag so Logstash knows which parser to use fields_under_root: true - type: log enabled: true paths: - /var/log/myapp/*.log fields: service: app fields_under_root: true multiline: # handle multi-line stack traces pattern: '^\[' negate: true match: after # Auto-discover Docker container logs - type: container paths: - /var/lib/docker/containers/*/*.log output.logstash: hosts: ["logstash:5044"]

Kibana — Querying and Dashboards

Once logs are in Elasticsearch, Kibana lets you search them with KQL (Kibana Query Language).

KQL — Kibana Query Language Examples
# Find all errors in the last hour status_code >= 500 # Find errors for a specific user status_code >= 500 AND user_id: "usr_123" # Full text search "NullPointerException" # Find slow requests (response time > 2 seconds) response_time > 2000 AND service: "api" # Exclude noise NOT path: "/health" AND NOT path: "/metrics" # Find all 404s for a specific endpoint status_code: 404 AND path: "/api/users/*"

Beyond search, Kibana lets you build dashboards — line charts of error rates over time, pie charts of status code distribution, geo maps of where traffic is coming from. All from your log data.

💡 Log what matters

Structure your application logs as JSON from day one. Instead of console.log("User 123 logged in"), do logger.info({ event: "login", userId: "123", ip: "1.2.3.4", duration_ms: 45 }). Structured logs are searchable, filterable, and alertable. Unstructured logs are a wall of text.

Elasticsearch Basics

Elasticsearch is a REST API at heart. You can interact with it directly using HTTP:

Terminal — Elasticsearch REST API
# Check cluster health curl http://localhost:9200/_cluster/health {"status":"green","number_of_nodes":1,"active_shards":12} # List all indices curl http://localhost:9200/_cat/indices?v health index docs.count store.size green logs-nginx-2024.01.15 142033 48.2mb green logs-app-2024.01.15 89204 31.8mb # Search — find all 500 errors curl -X GET "localhost:9200/logs-*/_search" -H 'Content-Type: application/json' -d' { "query": { "range": { "status_code": { "gte": 500 } } }, "size": 10, "sort": [{ "@timestamp": "desc" }] }' # Delete old indices (housekeeping) curl -X DELETE "localhost:9200/logs-nginx-2024.01.01"

✅ Module Summary
  • Elasticsearch stores and indexes logs as searchable JSON documents
  • Logstash ingests, parses, and transforms raw log text into structured data
  • Kibana provides the web UI for search, filtering, and dashboards
  • Filebeat is the lightweight agent that tails log files and ships them
  • Logstash pipelines have three sections: input → filter → output
  • Use grok to parse unstructured text logs; prefer structured JSON logs from your app
  • ELK solves logs; Prometheus solves metrics — you need both in production
  • Name indices with dates (logs-app-YYYY.MM.dd) for easy rotation and deletion
