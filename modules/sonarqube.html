SonarQube — Continuous Code Quality Inspection

What is SonarQube?

SonarQube is a static code analysis platform that automatically reviews your code for bugs, vulnerabilities, code smells, and duplications — before it ever runs in production. It integrates into your CI/CD pipeline so every pull request gets a quality gate.

🩺 Analogy — Annual health checkup for your code

A doctor doesn't wait for you to collapse before diagnosing problems — they run tests proactively. SonarQube does the same for code: it finds problems (bugs, security holes, technical debt) before they reach production. And like a doctor, it gives you a report card with what to fix and how urgent each issue is.

🐛
Bugs
Code that is clearly wrong or will cause incorrect behavior at runtime — null pointer dereferences, resource leaks, wrong comparisons.
🔐
Vulnerabilities
Security weaknesses that attackers can exploit — SQL injection, hardcoded passwords, insecure cryptography, XSS entry points.
🌫️
Code Smells
Code that works but is hard to maintain — too-long methods, deep nesting, duplicated blocks, misleading names. Accumulates as "technical debt".
☂️
Coverage
Percentage of your code exercised by unit tests. SonarQube imports test coverage reports and flags untested critical paths.

SonarQube Architecture

Developer pushes code │ ▼ CI Pipeline (Jenkins / GitHub Actions) │ ▼ SonarScanner runs on code (analyzes source files locally) │ ▼ Results sent to SonarQube Server ┌─────────────────────────────┐ │ SonarQube Server │ │ ├── Web Server (UI) │ │ ├── Compute Engine │ │ │ (processes reports) │ │ └── Database (PostgreSQL) │ └─────────────────────────────┘ │ ▼ Quality Gate evaluated PASS ✅ → PR can merge FAIL ❌ → PR blocked

Scanning Your Project

Create a sonar-project.properties file in your project root:

sonar-project.properties
sonar.projectKey=my-app sonar.projectName=My Application sonar.projectVersion=1.0 # Source and test directories sonar.sources=src sonar.tests=tests # Language (auto-detected if not set) sonar.language=java # Test coverage report (generated by your test framework) sonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml # Exclusions sonar.exclusions=**/vendor/**,**/node_modules/**
bash — Run scanner
# Using Docker (no install needed) docker run --rm \ -e SONAR_HOST_URL="http://localhost:9000" \ -e SONAR_TOKEN="your-token-here" \ -v "$(pwd):/usr/src" \ sonarsource/sonar-scanner-cli

Jenkins Integration

Jenkinsfile
pipeline { agent any stages { stage('Build') { steps { sh 'mvn clean package' } } stage('SonarQube Analysis') { steps { withSonarQubeEnv('SonarQube') { // configured in Jenkins sh ''' mvn sonar:sonar \ -Dsonar.projectKey=my-app \ -Dsonar.host.url=$SONAR_HOST_URL \ -Dsonar.login=$SONAR_AUTH_TOKEN ''' } } } stage('Quality Gate') { steps { timeout(time: 5, unit: 'MINUTES') { waitForQualityGate abortPipeline: true // pipeline fails if Quality Gate not passed } } } stage('Deploy') { steps { sh 'kubectl apply -f k8s/' } } } }

Quality Gates

A Quality Gate is a set of conditions that code must meet before it can be merged or deployed. The default "Sonar Way" gate blocks code if:

📊
Coverage < 80%
New code must have at least 80% test coverage. Encourages writing tests alongside features.
🔁
Duplication > 3%
New code must not duplicate more than 3% of existing code. Forces DRY (Don't Repeat Yourself) practices.
🐛
New Bugs > 0
Zero new bugs allowed in new code. Existing bugs (legacy debt) are tracked separately.
🔐
New Vulnerabilities > 0
Zero new security vulnerabilities. Any security issue blocks the merge.
💡 Custom Quality Gates

You can create custom quality gates in SonarQube UI under Quality Gates. Different projects can have different gates — stricter for payment services, more relaxed for internal tools.

Severity Levels

SonarQube Issue Severity
BLOCKER → Must fix NOW. Will definitely cause production issue. Example: NullPointerException on every request CRITICAL → Fix ASAP. High probability of production issue. Example: SQL query built from unvalidated user input MAJOR → Fix soon. Significant impact on maintainability or correctness. Example: Method is 500+ lines, unreachable code blocks MINOR → Fix when convenient. Small quality issue. Example: Variable not following naming convention INFO → Informational. No action required. Example: TODO comment found
