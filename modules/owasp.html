OWASP — Security Testing for DevSecOps

What is OWASP?

OWASP (Open Worldwide Application Security Project) is a non-profit foundation that produces free, open security resources. In DevOps, two OWASP tools are critical: the OWASP Top 10 (the most dangerous web vulnerabilities) and OWASP ZAP (an automated security scanner you embed in CI/CD).

🔒 Analogy — Security checklist before launch

Before an airplane takes off, pilots go through a safety checklist — not because they expect failure, but because missing one item can be catastrophic. OWASP gives you the security checklist for web applications. ZAP automates running that checklist on every build.

OWASP Top 10 — 2021

These are the 10 most critical web application security risks, ranked by frequency, exploitability, and impact:

🔓
A01 — Broken Access Control
Users can access resources they shouldn't. Example: changing ?user_id=123 to ?user_id=124 to view another user's data. #1 vulnerability in 2021.
🔐
A02 — Cryptographic Failures
Sensitive data exposed due to weak or missing encryption — passwords stored in plain text, HTTP instead of HTTPS, outdated TLS versions.
💉
A03 — Injection
Attacker sends hostile data as part of a command. SQL injection: '; DROP TABLE users;--. Also covers OS injection, LDAP injection, XSS.
🏗️
A04 — Insecure Design
Security flaws baked into the architecture — no rate limiting on login, no account lockout, no separation of privilege by design.
⚙️
A05 — Security Misconfiguration
Default passwords, open cloud storage buckets (S3), verbose error messages exposing stack traces, unnecessary features enabled.
📦
A06 — Vulnerable Components
Using libraries/frameworks with known CVEs — Log4Shell, Spring4Shell. Keep dependencies updated; scan with tools like Trivy, Snyk.
🎟️
A07 — Auth Failures
Broken authentication — weak passwords allowed, no MFA, session tokens not invalidated on logout, credential stuffing not blocked.
🔄
A08 — Data Integrity Failures
Code and data without integrity verification — insecure deserialization, unverified CI/CD pipeline updates, unsigned software packages.
📋
A09 — Logging Failures
No logging of login failures, no audit trail of sensitive actions, logs stored insecurely, no alerting on suspicious activity.
🌐
A10 — SSRF
Server-Side Request Forgery — attacker tricks your server into making requests to internal services. Used to access AWS metadata endpoints, internal APIs.

OWASP ZAP — Automated Scanner

ZAP (Zed Attack Proxy) is OWASP's flagship security testing tool. It acts as a proxy between your browser/test suite and your app, intercepting and analysing all traffic for vulnerabilities.

🕷️
Spider / Crawler
Automatically discovers all pages, forms, and endpoints in your app by following links and analysing JavaScript.
⚡
Active Scan
Actively attacks the app — sends malicious payloads to test for XSS, SQLi, path traversal, and more. Use only on test environments.
👁️
Passive Scan
Passively analyses traffic without sending attacks — safe on any environment. Finds missing security headers, cookies without Secure flag, etc.
🤖
Automation Framework
YAML-based config for CI/CD integration. Define scan rules, thresholds, and report formats — run headlessly in Jenkins or GitHub Actions.

ZAP in Jenkins CI/CD Pipeline

Jenkinsfile — DAST with ZAP
pipeline { agent any stages { stage('Build & Deploy to Staging') { steps { sh 'docker-compose up -d' sh 'sleep 15' // wait for app to start } } stage('OWASP ZAP Security Scan') { steps { script { sh ''' docker run --rm \ --network host \ -v $(pwd)/zap-reports:/zap/wrk \ ghcr.io/zaproxy/zaproxy:stable \ zap-baseline.py \ -t http://localhost:8080 \ -r zap-report.html \ -x zap-report.xml \ -J zap-report.json \ -I // don't fail on warnings, only errors ''' } } post { always { publishHTML([ reportDir: 'zap-reports', reportFiles: 'zap-report.html', reportName: 'ZAP Security Report' ]) } } } stage('Deploy to Production') { when { expression { currentBuild.result == null } // only if ZAP passed } steps { sh 'kubectl apply -f k8s/production/' } } } }

ZAP Scan Types

bash — ZAP scan commands
# Baseline scan — passive only, safe for prod-like environments (~2 min) docker run --rm ghcr.io/zaproxy/zaproxy:stable \ zap-baseline.py -t https://your-app.com -r report.html # Full scan — active attack, use ONLY on test/staging (~15-60 min) docker run --rm ghcr.io/zaproxy/zaproxy:stable \ zap-full-scan.py -t https://staging.your-app.com -r report.html # API scan — for REST APIs using OpenAPI/Swagger spec docker run --rm ghcr.io/zaproxy/zaproxy:stable \ zap-api-scan.py \ -t https://your-app.com/api/swagger.json \ -f openapi \ -r report.html

Dependency Scanning — OWASP Dependency-Check

Dependency-Check scans your project's libraries against the NVD (National Vulnerability Database) for known CVEs. Run it in CI to catch vulnerable packages before they ship.

Jenkinsfile — Dependency-Check stage
stage('Dependency Security Scan') { steps { dependencyCheck( additionalArguments: ''' --scan ./ --format HTML --format XML --out dependency-check-report --failOnCVSS 7 // fail pipeline if CVSS score >= 7 ''', odcInstallation: 'OWASP-DC' ) dependencyCheckPublisher( pattern: 'dependency-check-report/dependency-check-report.xml' ) } }
🔍 Alternatives to Dependency-Check

Trivy (by Aqua Security) is increasingly preferred in Kubernetes environments — it scans container images, filesystems, and Git repos for CVEs in one tool. Run trivy image your-app:latest in CI alongside ZAP for full coverage.

DevSecOps Pipeline — Full Security Flow

Code Commit │ ▼ ┌─────────────┐ │ SAST │ ← SonarQube (static code analysis) │ (build) │ finds bugs + security hotspots in source └──────┬──────┘ │ ▼ ┌─────────────┐ │ SCA │ ← OWASP Dependency-Check / Trivy │ (build) │ scans third-party libraries for CVEs └──────┬──────┘ │ ▼ ┌─────────────┐ │ Container │ ← Trivy image scan │ Scan │ checks Docker image layers for CVEs └──────┬──────┘ │ ▼ ┌─────────────┐ │ DAST │ ← OWASP ZAP │ (staging) │ attacks running app to find runtime vulns └──────┬──────┘ │ PASS ✅ │ ▼ Production Deploy
📌 SAST vs DAST — Key difference

SAST (Static Application Security Testing) — analyses source code without running it. Fast, catches issues early, but can't find runtime issues. SonarQube is a SAST tool.

DAST (Dynamic Application Security Testing) — attacks a running app. Slower, needs a live environment, but finds real exploitable vulnerabilities. ZAP is a DAST tool. Use both.
