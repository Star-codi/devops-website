Module 11 — Managed Kubernetes on AWS

Amazon EKS — Elastic Kubernetes Service

Why EKS?

Running Kubernetes yourself means managing the control plane — the API server, etcd, scheduler, controller manager. That's complex, requires high availability setup, and needs constant patching. EKS offloads all of that to AWS.

🏢 Analogy — Renting a managed office

Self-managed Kubernetes is buying a building and maintaining everything — plumbing, electricity, security. EKS is renting a fully managed office space. AWS handles the building (control plane). You just bring your furniture and staff (workloads and nodes).

🔧
Managed Control Plane
AWS runs and scales your API server and etcd across multiple AZs. No control plane VMs to patch or manage. 99.95% SLA.
🔗
AWS Integration
Native integration with IAM, VPC, ALB, EBS, EFS, ECR, CloudWatch, and Secrets Manager — no third-party plugins needed.
🛡️
Security
IAM Roles for Service Accounts (IRSA) lets pods assume IAM roles without storing credentials. Envelope encryption for Kubernetes secrets.
📈
Node Flexibility
Mix managed node groups, self-managed nodes, and AWS Fargate (serverless pods) in the same cluster.

Creating an EKS Cluster

The easiest way to create and manage EKS clusters is eksctl — a CLI tool purpose-built for EKS.

bash — Install eksctl
# Install eksctl (Linux/macOS) curl --silent --location \ "https://github.com/eksctl-io/eksctl/releases/latest/download/eksctl_$(uname -s)_amd64.tar.gz" \ | tar xz -C /tmp sudo mv /tmp/eksctl /usr/local/bin
cluster.yaml — eksctl config
apiVersion: eksctl.io/v1alpha5 kind: ClusterConfig metadata: name: my-cluster region: ap-south-1 # Mumbai — closest to India version: "1.29" managedNodeGroups: - name: ng-general instanceType: t3.medium minSize: 2 maxSize: 5 desiredCapacity: 2 volumeSize: 20 iam: withAddonPolicies: autoScaler: true albIngress: true cloudWatch: true
bash — Create cluster
# Create cluster (~15 mins) eksctl create cluster -f cluster.yaml # Update kubeconfig to connect kubectl aws eks update-kubeconfig --region ap-south-1 --name my-cluster # Verify kubectl get nodes

Node Groups — EC2 vs Fargate

🖥️
Managed Node Groups
EC2 instances managed by AWS — auto-patching, auto-scaling, auto-replacement of unhealthy nodes. Best for predictable, consistent workloads.
⚡
Fargate Profiles
Serverless — no EC2 to manage. AWS runs each pod on isolated compute. Pay per pod CPU/memory. Best for batch jobs and variable workloads.
🎛️
Self-Managed Nodes
You manage the EC2 instances yourself. Full control over AMI, configuration, GPU instances. Best when you need custom OS or hardware.
🔄
Karpenter
Open-source node autoscaler by AWS. Faster than Cluster Autoscaler — provisions nodes in seconds based on exact pod requirements.

IAM Roles for Service Accounts (IRSA)

IRSA is how pods in EKS securely access AWS services without hardcoding credentials. A pod assumes an IAM role via Kubernetes service account annotation.

bash — Create IRSA for S3 access
# 1. Create IAM OIDC provider for your cluster eksctl utils associate-iam-oidc-provider \ --cluster my-cluster --approve # 2. Create IAM service account with S3 policy eksctl create iamserviceaccount \ --cluster my-cluster \ --namespace default \ --name s3-reader \ --attach-policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess \ --approve
pod.yaml — use the service account
apiVersion: v1 kind: Pod metadata: name: s3-reader spec: serviceAccountName: s3-reader # linked to IAM role containers: - name: app image: amazon/aws-cli command: ["aws", "s3", "ls"] # works without credentials!

AWS Load Balancer Controller

To expose your apps via an AWS Application Load Balancer (ALB), install the AWS Load Balancer Controller. It provisions ALBs automatically when you create Kubernetes Ingress objects.

ingress.yaml — creates an ALB automatically
apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: my-app-ingress annotations: kubernetes.io/ingress.class: alb alb.ingress.kubernetes.io/scheme: internet-facing alb.ingress.kubernetes.io/target-type: ip spec: rules: - host: api.myapp.com http: paths: - path: / pathType: Prefix backend: service: name: my-app-service port: number: 80

Useful EKS Commands

bash — Day-to-day EKS operations
# List clusters eksctl get cluster # Scale a node group eksctl scale nodegroup --cluster my-cluster \ --name ng-general --nodes 4 # Upgrade cluster version eksctl upgrade cluster --name my-cluster --version 1.30 --approve # Delete cluster (removes all AWS resources) eksctl delete cluster --name my-cluster # View cluster info aws eks describe-cluster --name my-cluster --region ap-south-1
💰 Cost tip

EKS control plane costs ~$0.10/hour per cluster (~$72/month). Add EC2 node costs on top. For learning, create the cluster, practice, then delete it. Use eksctl delete cluster — it cleans up all AWS resources including VPC, security groups, and node groups.
